⚡ Exam-Eve Quick Guide — Datadog APM & Distributed Tracing

A consolidation of the key concepts, ports, environment variables and architecture rules tested across the 90 questions of the official certification.

1. Network Ports, Communication and Sockets

Port / Socket Protocol Purpose and Component
8126 TCP Trace Agent (APM): Listens for traces and spans sent by the client libraries (e.g., dd-trace-java, dd-trace-py, dd-trace-js).
/var/run/datadog/apm.socket Unix Domain Socket (UDS) Default high-performance mechanism on Kubernetes (DaemonSet) and Docker. Removes the overhead of TCP network ports on localhost.
8125 UDP DogStatsD: Ingests custom application metrics with low overhead and no synchronous blocking.
netstat -tlpn | grep 8126 CLI Essential command to check whether the Trace Agent process is listening on TCP port 8126 (LISTEN state).

2. APM Data Model Hierarchy

Entity Official Definition Critical Exam Rule
Trace The end-to-end path taken by a transaction through all microservices. Represented as a tree of spans that share the same trace_id.
Span An atomic, timed unit of work (method, database query, HTTP call). Belongs to EXACTLY 1 service. Required fields: name, start time, duration.
Root Span The root node that starts the trace when the request enters the instrumented system. Has no parent_id. It is where head-based sampling decides whether the trace is dropped or kept.
Child Span An operation executed during the parent span. Shares the same trace_id and references the parent's ID in the parent_id field.
Resource Splits service traffic into individual logical routes (e.g., GET /checkout, a SQL query). Dynamic identifiers (e.g., /users/123) are normalized via Quantization to GET /users/?.
Service Descriptive name of the microservice or backend component. Primary aggregation key. If two applications use the same service in the same env, their statistics are wrongly merged!

3. Essential APM Environment Variables

Environment Variable Value / Default What It Does (Exam Answer)
DD_SERVICE, DD_ENV, DD_VERSION Primary tags Unified Service Tagging: ties spans, metrics, logs and deployments into one cohesive experience. In Java, the default DD_ENV is none.
DD_LOGS_INJECTION=true Boolean Tells the tracer to enrich application logs with dd.trace_id and dd.span_id for automatic Log-to-Trace correlation.
DD_PROFILING_ENABLED=true Boolean Enables Continuous Profiling (Code Hotspots) to surface the methods and lines of code consuming CPU directly on the span.
DD_TRACE_SAMPLE_RATE Float (0.0 to 1.0) Controls the head-based sampling rate in the application (affects the volume of traces ingested by the Agent).
DD_APM_RECEIVER_PORT Port number Changes the TCP port the Trace Agent listens on in the Datadog Agent (default: 8126).
DD_KUBERNETES_NODE_LABELS_AS_TAGS Agent config Set on the Datadog Agent (DaemonSet) to map K8s node labels to APM and metric tags.

4. Data Retention and Filter Strategy

  • Indexed Spans in Trace Explorer: Default retention of 15 days (used for Flame Graph inspection, tag-based search and detailed analysis).
  • Trace Metrics and Custom Span-Based Metrics: Full 15-month retention at full resolution, enabling executive reports and year-over-year comparisons.
  • Head-based Sampling: The keep/drop decision is made when the root span is created. Limitation: if an error happens at the end of a request in a dropped trace, the error is lost.
  • Intelligent Retention Filter: Datadog's built-in system that automatically keeps traces with errors, high-latency percentiles (p99/p95) and endpoint diversity with no manual setup.
  • Custom Retention Filters: Let the organization define custom tag-based rules (e.g., @customer_tier:enterprise at 100%) for audit and compliance purposes.
  • Ingestion Control: Page under APM Setup & Configuration to inspect the volume of ingested span data per service and manage contracted quotas.

5. Visualizations, RED Metrics and Performance Analysis

  • RED Method: Rate (throughput/requests per second), Errors (error rate), Duration (response latency). Metric format: trace.<SPAN_NAME>.hits and trace.<SPAN_NAME>.errors.
  • Apdex (Application Performance Index): A 0-to-1 score measuring user satisfaction against a time threshold (T). It is configured per Service by users with the Datadog Admin or Standard role.
  • APM SLO Formula: Success Rate = (hits - errors) / hits.
  • Flame Graph: Stacked horizontal bar chart showing the hierarchy and execution time. A staircase pattern of many short consecutive spans signals the classic N+1 query problem.
  • Span Summary: The AVG % EXEC TIME column shows where the trace spent the largest share of total time; the ERROR RATE column shows the highest failure percentage.
  • Service Map: Highlights the mesh of connections between microservices and colors third-party dependencies with high error rates in red.
  • Error Tracking: Groups similar errors into "Issues" with regression detection and first/last-seen tracking via machine learning.
  • Marking Errors on Spans: The strict convention requires the error: 1 (or error: true) tag plus the error.type and error.message tags.
  • Correlation with RUM (Frontend): The backend must allow the x-datadog-trace-id, x-datadog-parent-id and traceparent headers in the CORS Access-Control-Allow-Headers header.
  • Async Queues (Kafka/SQS/RabbitMQ): The tracer injects tracing metadata into the message record headers, letting the consumer continue the same trace.
  • Universal Service Monitoring (USM): Uses eBPF probes in the Linux kernel to get service-level visibility (RED metrics) without code instrumentation.
