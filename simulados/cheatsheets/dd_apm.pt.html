⚡ Guia Rápido de Véspera de Prova — Datadog APM & Distributed Tracing

Consolidação de conceitos-chave, portas, variáveis de ambiente e regras de arquitetura cobrados nas 90 questões da certificação oficial.

1. Portas de Rede, Comunicação e Sockets

Porta / Socket Protocolo Finalidade e Componente
8126 TCP Trace Agent (APM): Escuta traces e spans enviados pelas bibliotecas clientes (ex: dd-trace-java, dd-trace-py, dd-trace-js).
/var/run/datadog/apm.socket Unix Domain Socket (UDS) Mecanismo padrão de alta performance no Kubernetes (DaemonSet) e Docker. Elimina o overhead de portas de rede TCP em localhost.
8125 UDP DogStatsD: Ingestão de métricas customizadas de aplicações com baixo overhead e sem bloqueio síncrono.
netstat -tlpn | grep 8126 CLI Comando essencial para verificar se o processo do Trace Agent está escutando na porta TCP 8126 (estado LISTEN).

2. Hierarquia do Modelo de Dados APM

Entidade Definição Oficial Regra Crítica para a Prova
Trace O caminho ponta a ponta percorrido por uma transação através de todos os microsserviços. Representado como uma árvore de spans que compartilham o mesmo trace_id.
Span Uma unidade atômica cronometrada de trabalho executado (método, query de banco, chamada HTTP). Pertence a EXATAMENTE 1 serviço. Campos obrigatórios: name, start time, duration.
Root Span O nó raiz que inicia o trace quando a requisição entra no sistema instrumentado. Não possui parent_id. É onde a amostragem na cabeça (Head-based Sampling) decide se o trace será descartado ou mantido.
Child Span Operação executada durante o span pai. Compartilha o mesmo trace_id e referencia o ID do pai no campo parent_id.
Resource Subdivide o tráfego do serviço em rotas lógicas individuais (ex: GET /checkout, query SQL). Identificadores dinâmicos (ex: /users/123) são normalizados via Quantization para GET /users/?.
Service Nome descritivo do microsserviço ou componente de backend. Chave de agregação primária. Se duas aplicações usarem o mesmo service no mesmo env, suas estatísticas são mescladas indevidamente!

3. Variáveis de Ambiente Essenciais do APM

Variável de Ambiente Valor / Padrão O que faz (Gabarito da Prova)
DD_SERVICE, DD_ENV, DD_VERSION Tags primárias Unified Service Tagging: amarra spans, métricas, logs e deployments em uma experiência coesa. Em Java, DD_ENV padrão é none.
DD_LOGS_INJECTION=true Booleano Comanda o tracer a enriquecer os logs da aplicação com dd.trace_id e dd.span_id para correlação automática Log-to-Trace.
DD_PROFILING_ENABLED=true Booleano Ativa o Continuous Profiling (Code Hotspots) para expor métodos e linhas de código consumindo CPU diretamente no span.
DD_TRACE_SAMPLE_RATE Float (0.0 a 1.0) Controla a taxa de Head-based Sampling na aplicação (afeta o volume de Ingestão de traces enviado ao Agent).
DD_APM_RECEIVER_PORT Número da porta Altera a porta TCP de escuta do Trace Agent no Datadog Agent (padrão: 8126).
DD_KUBERNETES_NODE_LABELS_AS_TAGS Config no Agent Configurada no Datadog Agent (DaemonSet) para mapear labels de nós K8s em tags de APM e métricas.

4. Retenção de Dados e Estratégia de Filtros

  • Spans Indexados no Trace Explorer: Retenção padrão de 15 dias (utilizados para inspeção de Flame Graphs, busca textual por tags e análise detalhada).
  • Métricas de Trace e Métricas Customizadas de Spans: Retenção completa de 15 meses com resolução total, viabilizando relatórios executivos e comparações anuais.
  • Head-based Sampling (Amostragem na Origem): Decisão de reter ou descartar é tomada na criação do root span. Limitação: se um erro ocorrer no final da requisição em um trace descartado, o erro é perdido.
  • Intelligent Retention Filters: Sistema inteligente nativo da Datadog que retém automaticamente traces com erros, percentis de alta latência (p99/p95) e diversidade de endpoints sem necessidade de configuração manual.
  • Custom Retention Filters: Permitem que a organização defina regras personalizadas por tag (ex: @customer_tier:enterprise com taxa em 100%) para fins de auditoria e conformidade.
  • Ingestion Control: Painel em APM Setup & Configuration para inspecionar volume de dados de spans ingeridos por serviço e gerenciar cotas contratadas.

5. Visualizações, Métricas RED e Análise de Desempenho

  • Método RED: Rate (throughput/requisições por segundo), Errors (taxa de erro), Duration (latência de resposta). Formato das métricas: trace.<SPAN_NAME>.hits e trace.<SPAN_NAME>.errors.
  • Apdex (Application Performance Index): Pontuação de 0 a 1 mensurando a satisfação do usuário baseada em limiar temporal (T). É configurado individualmente no nível de Service por usuários com papel Datadog Admin ou Standard.
  • Fórmula de SLO de APM: Taxa de Sucesso = (hits - errors) / hits.
  • Flame Graph: Gráfico de barras horizontais empilhadas mostrando a hierarquia e o tempo de execução. O padrão em degraus/escada de múltiplos spans curtos consecutivos indica o clássico problema N+1 de queries.
  • Span Summary: A coluna AVG % EXEC TIME indica onde o trace gastou a maior proporção do tempo total; a coluna ERROR RATE indica o maior percentual de falhas.
  • Service Map: Destaca a malha de conexões entre microsserviços e colore em vermelho dependências de terceiros com alta taxa de erro.
  • Error Tracking: Agrupa erros semelhantes em "Issues" com detecção de regressão e acompanhamento de primeira/última ocorrência via Machine Learning.
  • Marcação de Erro em Spans: A convenção estrita exige a tag error: 1 (ou error: true) e as tags error.type e error.message.
  • Correlação com RUM (Frontend): O backend deve autorizar os cabeçalhos x-datadog-trace-id, x-datadog-parent-id e traceparent no header de CORS Access-Control-Allow-Headers.
  • Filas Assíncronas (Kafka/SQS/RabbitMQ): O tracer injeta metadados de rastreamento nos record headers das mensagens, permitindo que o consumidor dê continuidade ao mesmo trace.
  • Universal Service Monitoring (USM): Utiliza sondas eBPF no kernel Linux para obter visibilidade de nível de serviço (métricas RED) sem instrumentação de código.
